# PROJECT_BOOTSTRAP.md — как подключить проект к Foundation (v0)

## Статус

v0. Проверен на одном проекте (Dispatching), правилом Governance пока
не является.

## Принцип

Подключение проекта — один файл в репозитории самого проекта. Канон не
копируется в проект: проект ссылается на версию канона.

## Что сделать

- Создать в корне проекта файл `FOUNDATION.md`.
- Указать канон: адрес репозитория Foundation и commit hash, на который
  ссылается проект.
- Указать, что проект принимает из канона. По умолчанию: блок
  «Инструкции для ИИ-исполнителя» из `CANON.md`.
- Указать, что не применяется. По умолчанию: Process Check, Governance
  Backlog, ревью. Проект вправе их не вводить.
- Указать, где живёт статус проекта (собственные файлы проекта,
  отдельный `PROJECT_STATUS.md` не требуется).
- Добавить в README проекта строку-ссылку на `FOUNDATION.md`, чтобы
  ИИ-исполнитель увидел связь при открытии проекта.

## Обратный канал

Практика проекта, которая может улучшить канон, фиксируется в
`governance/IDEAS_AND_DISCUSSION.md` Foundation с пометкой
«источник: <название проекта>». Это идея, а не решение: канон
меняется только через обычный путь Governance.

## Чего подключение не делает

- не навязывает проекту governance-процессы и ревью;
- не требует менять структуру и документы проекта;
- не делает канон обязательным для проекта юридически или технически:
  это договорённость для ИИ-исполнителя и человека.

## Открытые вопросы v0

- Как проект узнаёт, что канон изменился, и нужно ли обновлять hash.
  В v0 не регламентируется.
