GS-00Y
GS-00Y — Foundation как механизм формирования поведения исполнителя

Статус: Observation

Источник:
Release Review v1.0 → ER-4 → T-03

Наблюдение

Во время практического применения Foundation было замечено, что методология начинает выполнять функцию, выходящую за рамки простой регламентации процесса.

Foundation формирует такую последовательность действий, при которой соблюдение процесса становится более естественным, чем его нарушение.

Иными словами, система не принуждает исполнителя к правильному поведению, а архитектурно снижает вероятность неправильных действий.

Рабочая гипотеза

Foundation может являться не только системой описания процесса, но и системой формирования поведения участников посредством архитектуры самого процесса.

Основание

Наблюдение основано на практическом использовании Process Check во время проведения Release Review v1.0.

Во время аудита неоднократно происходила добровольная остановка обсуждения и возврат к текущему этапу без внешнего принуждения.

Возможное значение

Если гипотеза подтвердится, данный принцип может стать одной из фундаментальных характеристик Foundation.

Статус решения

Не рассмотрено.

Требует отдельного Governance Review после завершения Release Review.

GS-00Z
GS-00Z — Область действия вывода ограничена областью подтверждённых фактов

Статус: Observation

Источник:
Release Review v1.0 → ER-5 → T-02

Наблюдение

Во время проверки MANIFEST.md было установлено, что достоверность архитектурного вывода определяется не только корректностью анализа, но и полнотой подтверждённых фактов.

В результате сформулирован следующий рабочий принцип:

Область действия любого вывода не может быть шире области подтверждённых фактов.

Пример

Если проверен весь документ, вывод может относиться ко всему документу.

Если проверена только часть документа, вывод может относиться исключительно к проверенной части.

Рабочая гипотеза

Данный принцип может стать общим ограничением для:

Release Review;
Governance Review;
архитектурных аудитов;
анализа изменений;
проверки документации.
Основание

Наблюдение возникло в ходe аудита MANIFEST.md, когда Process Check не позволил распространить выводы на части документа, не подтверждённые фактическими данными.

Возможное значение

Принцип способен повысить достоверность всех процедур проверки в Foundation и снизить вероятность необоснованных архитектурных выводов.

Статус решения

Не рассмотрено.

Требует отдельного Governance Review после завершения Release Review.

GS-00A
GS-00A — Контроль полноты Repository Study

Статус:
Observation / Requires Governance Consideration

Источник:
Repository Study Read Set v0.1

Наблюдение

Во время текущего repository study исполнитель объявил контекст проекта изученным до того, как был прочитан весь заявленный корпус. В частности, Governance_Backlog.md был прочитан только после такого заявления.

Выявленная проблема:

Канонический recovery route и полное изучение repository context являются разными операциями. Чтение recovery route не подтверждает, что весь заявленный corpus был прочитан.

Рабочий принцип:

Исполнитель не должен объявлять Repository Study завершённым без проверяемого Read Set, содержащего каждый файл заявленного scope, его идентификатор источника (например blob SHA), статус чтения и сведения о failed/unread файлах.

Рабочее требование:

Статус READ_COMPLETE может быть выставлен только при успешном чтении каждого файла заявленного scope и отсутствии обязательных unread/failed файлов.

Evidence:

governance/Repository_Study_Read_Set_v0.1.md

Статус решения:

Не рассмотрено.

Требует отдельного Governance Review. Foundation v1.0 не изменяется.
