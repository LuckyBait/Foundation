# PILOT_PLAN.md — разовая проверка Foundation на реальном контенте

## Статус

Разовый план, не Governance-правило. Цель — получить факт, а не мнение:
сколько трения создаёт текущий процесс на реальном материале.

## Почему это нужно именно сейчас

Governance Backlog содержит 10+ пунктов о процессе и ни одного
content-артефакта. Без этого возврат Foundation к организации знаний
остаётся намерением, а не фактом.

## Материал для пилота

Один небольшой, реально существующий фрагмент знания из другого
проекта владельца — то, что сейчас существует только в заметках
или переписке, не оформлено документом.

## Процедура

1. Зафиксировать время старта.
2. Провести фрагмент через полный маршрут: CANON.md → Foundation Core →
   PROJECT_STATUS.md → Process Check → (если применимо) Governance Backlog
   → Documentation Lifecycle.
3. На каждом шаге фиксировать сколько заняло по времени и потребовалось
   ли обращение к governance-документам, не относящимся напрямую к содержанию.
4. Зафиксировать итоговый артефакт знания (готовый документ).
5. Зафиксировать итоговое время и список шагов, которые были чисто
   процедурными (не добавляли ничего к содержанию документа).

## Критерий результата

Не "процесс хороший/плохой" — а конкретное отношение:

`время на процедурные шаги : время на содержательную работу`

Записать факт в `governance/IDEAS_AND_DISCUSSION.md` без предрешения
вывода. Если отношение окажется явно перекошено в сторону процедуры —
это подтверждает диагноз фактом, и даёт основание для конкретного
упрощения маршрута.

## Что пилот не делает

Не меняет Foundation v1.0. Не создаёт нового Governance-правила
автоматически — результат пилота идёт в Ideas/Discussion и требует
отдельного решения.
