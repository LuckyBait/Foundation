# Принцип полноты поиска и снимка репозитория

## Статус

Концептуальная запись / анализ исполнения.

Этот документ сохраняет принцип, выявленный в ходе repository-only анализа.
Он сам по себе не является Governance authority и не изменяет правила Foundation v1.0.

## Основной принцип

Нахождение релевантной информации не означает завершения поиска по репозиторию.

Исполнитель не должен прекращать поиск только потому, что найден правдоподобный или на первый взгляд достаточный ответ.

Вывод может считаться завершённым только после того, как исполнитель:

1. определил проверяемый снимок репозитория;
2. определил область вопроса;
3. определил необходимые классы доказательств и направления поиска;
4. проверил все определённые направления до установленного условия завершения;
5. зафиксировал полученный набор доказательств;
6. проверил полноту покрытия заявленной области;
7. только после этого сформировал вывод.

## Идентификация снимка репозитория

Поиск по репозиторию должен быть привязан к однозначно идентифицируемому состоянию репозитория.

Как минимум, запись поиска должна содержать:

- репозиторий;
- ветку;
- SHA коммита;
- при необходимости SHA дерева;
- заявленную область поиска.

SHA коммита устанавливает, **какое состояние репозитория было проверено**.

Сам по себе SHA коммита не устанавливает, что поиск был полным.

## Полнота покрытия поиска

Полнота поиска требует заранее определённой области и перечня направлений поиска.

Такой перечень должен определять, когда это применимо:

- репозиторий и снимок;
- проверяемый вопрос;
- файлы и каталоги, входящие в область;
- явно исключённые области;
- классы доказательств;
- варианты терминологии;
- функциональные и структурные эквиваленты;
- релевантные Issues;
- релевантные Pull Requests;
- авторитетные Governance records;
- конкретные практические прецеденты;
- условие завершения проверки.

Поиск должен продолжаться до выполнения заявленного условия завершения.

## Важное различие

Нельзя смешивать два независимых свойства.

### Идентичность снимка

> Какое состояние репозитория было проверено?

Это устанавливается идентификатором коммита и, при необходимости, дерева.

### Полнота поиска

> Была ли заявленная область репозитория действительно проверена настолько, чтобы поддерживать сделанный вывод?

Это устанавливается перечнем направлений поиска и подтверждением их завершения.

Корректный SHA без подтверждённого покрытия поиска **не является доказательством полного поиска**.

Полный поиск без однозначного снимка репозитория **не является полностью воспроизводимым**.

Для воспроизводимой проверки необходимы оба свойства.

## Обнаружение не завершает поиск

Если релевантное доказательство найдено, оно добавляется к набору доказательств, но оставшиеся направления поиска всё равно должны быть проверены.

Правильная последовательность:

    определить область
        ↓
    определить снимок репозитория
        ↓
    определить направления поиска
        ↓
    выполнить поиск
        ↓
    обнаружено доказательство?
        ↓
    продолжить до выполнения условия покрытия
        ↓
    проверить полноту покрытия
        ↓
    сформировать вывод

Неправильная последовательность:

    выполнить поиск
        ↓
    найден правдоподобный ответ
        ↓
    сформировать вывод

## Изменение состояния репозитория

Если после завершения поиска репозиторий изменился, новое состояние является другим снимком доказательств.

Последующий вывод должен однозначно указывать, опирается ли он на:

- ранее проверенный снимок; или
- новый снимок репозитория, для которого требуется новая проверка.

Новое доказательство, появившееся после зафиксированного SHA, не означает, что предыдущий поиск был неполным.

И наоборот, доказательство, которое уже существовало в проверенном снимке, но не попало в фактически выполненное покрытие поиска, является **ошибкой покрытия** и не должно молча рассматриваться как новое состояние репозитория.

## Граница Process Check

Этот принцип не предоставляет исполнителю полномочий самостоятельно создавать новые Governance rules.

Он устанавливает требование к качеству, полноте и воспроизводимости repository analysis.

Любое последующее нормативное внедрение этого принципа должно проходить через существующий Governance process.

## Предполагаемый результат

Цель принципа — предотвратить повторяющийся сценарий:

> найден релевантный artifact → сделан преждевременный вывод → позднее обнаружено уже существовавшее доказательство → анализ начинается заново.

Желаемое свойство:

> **Исполнитель должен уметь отличать «я нашёл ответ» от «я проверил заявленную область поиска настолько полно, чтобы сделать вывод».**

## Будущая операционная концепция

В будущем может потребоваться явное durable state, например:

`ПОИСК_ВЫПОЛНЯЕТСЯ`

`ПОИСК_ЗАВЕРШЁН`

`ПОКРЫТИЕ_НЕПОЛНОЕ`

`СНИМОК_ИЗМЕНЁН`

Эти состояния являются только направлением проектирования на данном этапе и пока не являются авторитетными правилами.

## Правило сохранения

Эта запись существует для сохранения концепции до проектирования её реализации.

Сам этот документ не создаёт новую Governance authority, реестр, планировщик или автоматизированную систему поиска.
